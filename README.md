# WordShield Corp

Корпоративный сервис для подготовки документов к отправке во внешние языковые модели: локальное обнаружение чувствительных данных, управляемая замена плейсхолдерами и обратное восстановление.

**Это отдельный репозиторий WordShield Corp; основная ветка — `main`. Не устанавливать поверх личной версии и не подключать к её данным или ключам.** Личная версия находится в отдельном [wordshield-local](https://github.com/Syrmus/wordshield-local). Это не сертифицированная система защиты информации и не гарантия обнаружения всех данных.

## Для сотрудников

Сотрудники работают на Windows через браузер. Устанавливать WordShield или модели на рабочие компьютеры не нужно. Загрузите DOC/DOCX, выберите категории и язык плейсхолдеров, проверьте переключатели, скачайте DOCX или Markdown. Перед отправкой в публичную модель просмотрите результат. Чтобы вернуть исходные значения после редактирования DOCX, выберите исходную сессию в разделе восстановления.

## Где работает сервис

Приложение и модели разворачиваются **на корпоративном Linux-сервере**, через Docker Compose. Для ускорения используется NVIDIA GPU; CPU-режим предусмотрен для проверки совместимости. Доступ — по внутреннему HTTPS-адресу, вход — через корпоративный OIDC-провайдер. Для начального пилота доступны локальные аккаунты, создаваемые администратором.

Сервер, данные, ключи и модели находятся внутри инфраструктуры компании. Доступ сотрудников из дома организуют ИТ через принятую в компании систему доступа к внутренним приложениям. Конкретная система удалённого доступа не является зависимостью WordShield.

## Что реализовано в пилоте

- Linux-адаптер сетевого ограничения детекторов и LibreOffice через seccomp, проверка запрета IPv4/IPv6.
- Временный tmpfs, отказ при активном swap, master key в отдельно смонтированном файле-секрете.
- Выбор CPU или CUDA для детекторов. Скорость и совместимость конкретного GPU ещё требуют испытаний.
- OIDC Authorization Code + PKCE, проверка подписи/issuer/audience/nonce, одноразовый вход; доступ по корпоративным группам. Реальный корпоративный провайдер ещё не подключён.
- Отдельные кабинеты, блокировка, локальный аварийный администратор; открытая регистрация выключена. Корпоративному пользователю нельзя задать локальный пароль.
- Один процесс приложения и один анализ одновременно, очередь до 20 заданий, до двух незавершённых заданий на пользователя. Состояния и контрольные точки сохраняются; незавершённые анализы возобновляются при запуске.
- Экспорт DOCX/MD, русский и английский язык замен, восстановление старых и новых алиасов, общий срок хранения 90 дней.

Пилот использует SQLite и один экземпляр приложения. PostgreSQL, распределённые workers, полный аудит событий и полноценное управление профилями обработчиков из админки пока не реализованы. Не масштабировать приложение несколькими репликами.

## Проверка установки

`/healthz` подтверждает только работу приложения, не готовность моделей. На целевом сервере обязательно выполнить `sh deploy/corp/corp.sh --gpu check`: синтетический документ проходит оба детектора, рендер, экспорт и восстановление. Это техническая проверка, не измерение полноты обнаружения персональных данных.

В этой поставке нет весов моделей, пользовательских файлов, ключей или настроек корпоративной сети. Перенос в закрытый контур описан в инструкции установки. Установка зависимостей требует сети только на этапе подготовки.

## Важное ограничение

Ни один детектор не гарантирует нахождение 100% конфиденциальных данных.
Проверяйте обезличенный результат перед передачей третьим лицам. Markdown не
сохраняет исходную вёрстку. Восстановление изображений пока не поддерживается.

## API

- `POST /api/sessions` — загрузить DOC/DOCX;
- `GET /api/sessions/{id}/findings` — получить находки;
- `PATCH /api/sessions/{id}/decisions` — изменить решения;
- `POST /api/sessions/{id}/export?format=docx|md` — экспортировать;
- `POST /api/restore` — восстановить известные алиасы в DOCX;
- `DELETE /api/sessions/{id}` — удалить сессию и её ключ.

## Приватность репозитория

В репозитории должны находиться только исходный код, синтетические тесты и
обобщённые конфигурации. Реальные документы, сессии, логи, отчёты стенда,
адреса устройств и персональные настройки исключены через `.gitignore` и не
должны добавляться вручную.
