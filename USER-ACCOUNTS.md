# Личные кабинеты WordShield

## Для пользователя

1. Откройте прежний адрес сервиса. Доступ по сети пока требует Tailscale.
2. Введите свой логин и пароль. Если аккаунта нет, нажмите «Зарегистрироваться».
3. После регистрации попросите администратора одобрить заявку. Письма не отправляются.
4. Загружайте файлы как раньше. Сессии, оригиналы, результаты и постоянные замены личные.
5. В «Личном кабинете» можно изменить пароль и выйти. Смена пароля завершает все входы.

## Для администратора

При первом включении появляется аккаунт `admin` с прежним паролем сервиса.
Прежние сессии и постоянные замены принадлежат ему. Ничего не переносится и не удаляется.
Старые браузерные входы не принимаются: потребуется войти с логином.

Откройте «Личный кабинет» → «Управление пользователями»:

- создайте аккаунт с ролью «Пользователь» или «Администратор»;
- одобрите заявку на регистрацию (заявка сама по себе доступа не даёт);
- заблокируйте аккаунт или разблокируйте ранее заблокированный;
- при необходимости задайте новый пароль и передайте его лично.

Нельзя заблокировать себя или последнего активного администратора.
Блокировка отзывает браузерные сессии. Начатая обработка может завершиться, но
заблокированный пользователь не получит результат. Данные не удаляются при блокировке:
общий срок 90 дней от загрузки сохраняется, в том числе для заблокированных аккаунтов.

Админка не позволяет просматривать чужие документы, а документные маршруты
проверяются в личном хранилище даже для администратора. Однако администратор —
доверенная роль: возможность сбросить пароль позволяет ему войти от имени
пользователя. Это не защита от владельца сервера или скомпрометированного процесса.

## Миграция и устройство

Включение: `WORDSHIELD_USERS_ENABLED=1`, обязательно существующий
`WORDSHIELD_AUTH_FILE`. При выключенном флаге остаётся прежний одиночный вход.
Установщик поддерживает `--enable-users`, проверяет отсутствие анализа перед
обновлением и возвращает прежний код/настройки, если новая служба не запустилась.

Добавляется `accounts.sqlite3` (600) с scrypt-хешами паролей и хешами случайных
браузерных токенов. Первичная запись владельца создаётся однократно; повторный
запуск не сбрасывает пароль или роли. Доступные в браузере токены не содержат ID
пользователя и проверяются по базе на каждом запросе. Cookies: Secure, HttpOnly,
SameSite=Strict, 30 дней; выход, блокировка и смена пароля отзывают доступ.
Число попыток входа и регистраций ограничено, счётчики переживают перезапуск.

Хранилище владельца остаётся на прежнем месте. Новые хранилища —
`users/<случайный внутренний ID>/`, с отдельными базами и зашифрованными файлами.
Исходный логин не используется как путь. Файлы, таблицы алиасов, словари,
контрольные точки и поиск сессии для восстановления не объединяются между
пользователями. Ключ macOS Keychain общий для серверного процесса, отдельные
ключи сессий сохраняются. Разделение прикладное, не по системным аккаунтам.

На запрос выбирается только его хранилище. Контекст не имеет неявного возврата
к владельцу. Фоновая задача получает конкретный экземпляр сервиса владельца.
Локальные детекторы общие, одновременно выполняется один анализ. Очистка
просроченных данных и возобновление работают по всем существующим хранилищам.

## Откат

Не запускать старую и новую версии одновременно на одном порту/хранилище.
Остановить службу, вернуть сохранённые установщиком исходники и launchd plist,
затем запустить службу. Новые базы и каталоги не удалять. Старая версия видит
только прежнее хранилище и использует прежний одиночный пароль из browser-auth.json
(не новый пароль, если его меняли в аккаунте). Не раздавать этот пароль коллегам.
При повторном включении новой версии аккаунты и их данные снова доступны.
Такой откат сохраняет данные, но временно отключает вход новых пользователей.

## Граница этой задачи

Tailscale, ограничения сети и локальные модели не меняются. Аккаунты не делают
сервис доступным из публичного интернета. Для коллег без Tailscale необходим
отдельный этап публикации с HTTPS, защитой входа и проверкой конфигурации.
Переход на отдельного пользователя macOS не выполняется.

Тесты: старое хранилище, все документные маршруты, восстановление по алиасам и
явному ID, приватность словаря, роли, регистрация/одобрение, блокировка и отзыв,
пароли, срок входа, CSRF, конкурирующие запросы, перезапуск анализа и очистка
данных заблокированного пользователя. Синтетические данные, без облачного анализа.

Проверка 02.10.2026: 199 автоматических тестов прошли на Mac mini. По действующему
HTTPS-адресу проверены вход `admin`, кабинет, управление пользователями и справка.
Синтетический двухъязычный документ прошёл локальный анализ, экспорт DOCX/MD и
восстановление: 113 замен, 0 спорных находок, 113 восстановленных вхождений.
