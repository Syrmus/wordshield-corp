# Проверки пилотной поставки Corp

Дата проверки: 10 октября 2026 года. Результаты относятся к исходникам этой поставки, не к корпоративному серверу заказчика.

## Выполнено

- Собран тестовый образ Python 3.12 / Debian Bookworm, Linux ARM64.
- 240 тестов прошли в контейнере без сети, с read-only root filesystem, без capabilities, без повышения привилегий, под UID/GID 10001.
- Среди тестов: старые DOCX/MD/алиасы/кабинеты; OIDC state, PKCE, подпись, issuer/audience/nonce, expiry, replay; изоляция ролей; запрет локального пароля для OIDC; валидация HTTPS-origin; bootstrap без перезаписи ключей; seccomp IPv4/IPv6 и Unix IPC; реальный LibreOffice на синтетическом DOCX.
- Для теста синтетического LibreOffice проверка отсутствия swap подменена только внутри теста: локальная Linux VM имеет swap. Отдельный тест подтверждает отказ приложения при swap. Полный production preflight этой VM намеренно не объявляется прошедшим.
- Собран полный runtime-образ с CPU PyTorch 2.14.0+cpu, GLiNER2 и закреплённым OPF. Их импорт проходит при активном системном запрете сети. Это не запуск моделей на реальных весах.
- Docker Compose CPU/GPU-конфигурации проходят `config --quiet`; установочный shell-скрипт проходит синтаксическую проверку.
- Gitleaks 8.24.3 не нашёл секретов в подготовленном diff и текущем дереве публикуемых файлов. Сканирование выполнялось локально, без сети; это автоматическая проверка, не гарантия отсутствия любых персональных данных и не полный аудит прежней истории репозитория.
- Изменения изолированы в ветке `corp`; другие установки не обновлялись.

## Не выполнено

- Полный анализ настоящими весами в новом Linux runtime и синтетический `corp.sh check` на сервере без swap.
- Сборка и исполнение GPU-образа на Linux x86_64 с A100/H100/RTX 6000, замеры VRAM и производительности, сравнение точности CPU/GPU.
- Интеграция с настоящим корпоративным OIDC-провайдером, TLS/DNS и правилами egress компании.
- Пилот 20 сотрудников, нагрузка, реальный рестарт во время GPU-анализа, корпоративный Word, бэкапы/откат в целевой инфраструктуре.
- Полный аудит зависимостей, лицензий и прежней истории Git; промышленная аттестация.

Не подключать реальные чувствительные документы до приёмки по `SECURITY.md`. Успешные unit/integration-тесты не заменяют эти испытания.
